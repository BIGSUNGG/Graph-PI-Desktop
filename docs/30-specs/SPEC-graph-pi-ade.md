# SPEC-graph-pi-ade

한 줄 요약: Pi 전용 데스크톱 ADE가 상태 보드·채팅·오케스트레이션·히스토리 네 화면에서 무엇을 보여주고 어떤 조작을 허용하는지 확정한다.

관련 문서: [[ADR-0001-standalone-ade-over-orca-plugin]], [[ADR-0002-pi-session-jsonl-data-source]], [[orca-cli-and-pi-sessions]], [[30-specs/SPEC-hub-orchestration]]

## 목적

Pi 세션이 어디서 돌고 무엇을 했는지 한 화면에서 파악하고, 과거 대화를 다시 찾고, 필요하면 그 자리에서 이어서 실행하기 위해 만든다. Orca가 제공하는 실행·워크트리 관리를 버리지 않으면서, Orca가 제공하지 않는 대화 열람과 그래프 표현을 얹는다.

## 대상 사용자

자기 PC에서 Orca로 Pi 세션·워크트리를 여러 개 돌리는 1인 사용자. 작업자는 본인 한 명이며, 조직 공유·다중 사용자 권한은 다루지 않는다.

## 포함 범위

- **앱 형태**: Orca와 독립된 데스크톱 앱. 작업명은 저장소 이름을 따라 Graph PI Desktop으로 둔다.
- **앱 스택**: Electron + React + TypeScript. 창·파일 감시·PTY·패키징을 검증된 방식으로 처리하고 Orca 소스의 패턴을 그대로 참고한다.
- **프로젝트 단위**: Orca 워크스페이스 기준. 앱의 모든 목록·그래프·히스토리는 선택한 워크스페이스에 속한 데이터로 한정한다.
- **화면 배치**: 좌측 내비게이션 + 단일 뷰. 보드, 채팅, 오케스트레이션, 히스토리 네 항목.
- **워크트리 그룹**: 여러 레포의 워크트리를 하나의 작업 단위로 묶는다(`feature/login` = Server·Client·Contract). 그룹은 앱이 직접 정의해 앱 데이터 폴더에 저장하고(이름·소속 워크트리·순서·허브 세션), Orca 에는 없는 개념이다. 보드는 선택한 그룹의 허브 세션과 워크트리만 그린다.
- **상태 보드·그래프**: 세션 노드와 세 종류의 관계선. 서브에이전트 호출은 노드로 그리지 않고, 각 세션에 최근 호출한 도구 1개를 표시한다. 배치는 그룹 허브 세션을 최상단에 두고 워크트리 상하위 관계를 따르는 세로 계층 트리이며, 같은 워크트리의 세션은 그 열 안에 세로로 늘어선다.
- **성능 목표**: 동시 20세션에서 보드가 끊김 없이 다시 그려져야 한다.
- **채팅**: 세션 메시지 열람과 프롬프트 전송.
- **오케스트레이션 대시보드**: Run·Task·Worker·Gate 조회.
- **히스토리 브라우저**: 최근 30일 목록과 본문 검색.
- **실행 제어**: Pi 세션 재개, 새 Pi 세션 시작, 실행 중 세션에 입력·중단. 새 세션의 모델 목록은 Orca가 실행 가능하다고 알려준 모델만 조회해 보여준다.
- **외부 세션**: Pi 세션 파일의 경로가 Orca 워크트리에 없으면 목록에서 빼지 않고 `외부` 라벨로 표시한다. 열람은 되고 제어는 되지 않는다.
- **프로젝트·워크트리 관리**: 프로젝트 추가, 워크트리 생성·이름/메타 수정·삭제·숨김, 상위/하위 워크트리 관계.
- **데이터 갱신**: Pi 세션 파일 감시 + Orca 상태 3초 폴링.
- **오류 표시**: 상단 배너 + 마지막 성공 값 유지.

## 제외 범위

- Pi 이외 에이전트(Claude Code, Codex 등)의 실행·대화 표시. 앱은 Pi 전용이다.
- 오케스트레이션 상태를 앱에서 **변경**하는 기능(Task 생성·Gate 결정 등). 대시보드는 조회 전용이다. 사용자가 조작 범위에서 선택하지 않았다.
- Orca 자체 UI 수정, `orca-main` 포크, 플러그인 배포.
- 다중 사용자·원격 공유·모바일·웹 버전.
- 앱 실행 시 Orca를 자동으로 켜는 동작. 미실행 시에는 열람만 한다(아래 상태 표).
- 세션 자동 정리·삭제 정책.

## 사용 흐름

### 1. 진입

1. 사용자가 앱을 실행한다.
2. 앱이 Orca 연결 상태를 확인한다.
3. Orca가 실행 중이면 마지막으로 보던 워크스페이스의 보드 화면을, 아니면 상단 배너와 함께 히스토리 화면을 보여준다.

### 2. 상태 보드

1. 좌측 내비에서 보드를 고른다.
2. 사이드바에서 그룹을 고른다. 마지막으로 보던 그룹이 기본이고, 그룹을 고르면 그 그룹의 허브 세션과 워크트리만 보드에 그려진다. 그룹 행을 고르면 그 그룹의 허브 세션이 선택되고, 이미 활성인 그룹 행을 다시 고르면 목록 접기·펴기만 한다.
3. 사이드바에서 워크트리를 고르면 그 워크트리가 선택되고, 바로 아래에 그 워크트리의 활성 세션이 항상 펼쳐진 계보 트리로 보인다. 트리는 부모 세션 바로 아래에 자식 세션을 재귀적으로 들여쓰고 `├─`·`└─` 가이드로 잇는다. 같은 부모의 자식은 시작 시각 순으로 정렬한다. 다른 워크트리에 속한 자식 세션은 원래 워크트리 위치에 남기고 `↖`와 상위 세션 제목 툴팁으로 부모를 표시한다. 부모가 삭제됐거나 표시 목록 밖이면 그 세션은 최상위로 표시한다. 감사 세션은 제목 옆 `Audit` 배지로 구분한다. 세션 행은 상태 점·세션 제목·마지막 활동 시각을 보여준다. 워크트리 안의 세션 계보에는 접기 상태가 없으며, 워크트리를 다시 골라도 접히지 않는다. 다른 그룹을 골랐다가 돌아와도 세션 계보는 펼쳐져 있다. 세션이 없는 워크트리에는 `세션 없음` 안내 행이 보인다. 세션을 고르면 그 세션이 선택되고, 보드에서는 상세와 인라인 채팅이 그 세션으로 바뀌며, 채팅에서는 그 세션 채팅이 열린다. 히스토리에서는 그 세션 채팅으로 이동하고, 오케스트레이션에서는 화면을 유지한 채 선택만 갱신한다. 워크트리 안의 세션 계보는 항상 펼쳐져 있으므로 보드·채팅·히스토리에서 세션을 골라도 선택만 갱신된다.
4. 앱이 선택한 그룹의 허브 세션을 최상단 전폭 카드로 그리고, 그 아래에 루트 워크트리, 다시 그 아래에 하위 워크트리 열을 놓는다. 관계선은 허브→루트 세로 트렁크, 열 위를 가로지르는 버스, 각 열로 내려가는 세로 연결 순서로 이어지고, 허브→직계 자식 세션·부모-자식 세션·같은 워크트리·워크트리 상하위 관계도 선으로 잇는다. 감사 세션은 제목 옆 `Audit` 배지로 구분한다. 각 세션에는 최근 호출한 도구 1개를 붙인다. 워크트리가 없는 그룹도 허브 카드와 `빈 그룹 — 워크트리를 추가하세요.` 안내를 보여준다. 세션 노드를 클릭하면 그 세션이, 세션 노드가 아닌 워크트리 카드를 클릭하면 그 워크트리가 선택된다.
5. 노드를 선택하면 상세에 세션 제목, 모델, 시작 시각, 마지막 활동, 토큰 사용량이 보인다. 그 아래에 상위 세션과 하위 세션 계보가 트리로 보이고, 다른 워크트리 세션은 워크트리 이름 배지로 구분한다. 허브 세션은 워크트리에 속하지 않으므로 워크트리 자리에 `그룹 폴더` 로 표시한다.
6. 세션 상세 아래에 그 세션의 채팅이 붙고, 채팅 화면과 같은 턴 표현(생각·도구 포함)으로 보인다. 상세에서 바로 프롬프트를 보낼 수 있고(전송 조건은 §3 4~5항을 따른다), 채팅 영역 경계를 끌어 120~720px 사이에서 높이를 바꾼다(기본 280px). 조절한 높이는 다시 그려도 유지되고, 내용이 화면보다 길면 상세 안에서 스크롤한다. 전체 화면 채팅은 좌측 내비 `채팅`으로 연다.
7. 상세에서 재개·중단을 실행한다.
8. 허브 세션을 제거하면 확인 창에 허브 재생성 안내를 보여주고, 그룹 관리용 허브 세션을 새로 만든다(워크트리에 속하지 않고 부모 저장소 폴더에서 시작, 모델은 지운 허브의 모델, 첫 프롬프트 없음). 새 허브 세션이 선택된다. 허브를 직접 지정하는 UI는 두지 않는다.
9. `Ctrl` + `+`/`-`로 보드를 확대·축소하고, 빈 곳을 드래그해 이동한다. 이동은 세션 노드가 하나 이상 보이는 범위로 제한한다.

### 3. 채팅

1. 채팅 목록은 현재 선택된 그룹의 세션만 보여준다. 부모 세션 아래에 자식 세션을 재귀적으로 들여쓰고 `├─`·`└─` 가이드로 잇는다. 다른 워크트리 자식은 원래 위치에 두고 부모 표시를 붙이며, 감사 세션은 `Audit` 배지로 구분한다.
2. 워크트리를 고르면 그 워크트리에서 부모가 없거나 부모가 다른 워크트리에 있는 루트 세션, 세션을 고르면 그 세션의 채팅이 바로 열린다. 사이드바에서 세션을 고르는 경우에도 같은 규칙을 따른다.
3. 메시지가 시간순으로 보인다. 사용자 메시지는 오른쪽 강조 버블, assistant 메시지는 왼쪽 답변으로 보인다. 에이전트의 생각과 도구 사용은 접이식 블록 안에 함께 표시하고, 도구마다 이름과 결과 한 줄을 보여준다. 진행 중에는 `Thinking...`, 답변이 나온 뒤에는 `Thought for Ns`로 표시한다. 사용자 메시지에는 역할 라벨을 두지 않고 시각만, 에이전트의 Thinking 블록과 완료 답변 각각에는 해당 시각, 도구 행에는 호출 시각을 표시한다. compaction 이벤트는 구분선으로 표시한다. 최신 에이전트 턴은 펼친 상태로 시작한다.
4. 입력창에 프롬프트를 쓰고 전송한다.
5. 실행 중 세션이면 PTY로 전달되고, 전송 중·전송됨·실패가 표시된다. 실행 중이 아닌 세션이면 재개 여부를 먼저 묻는다.
6. 새 세션은 새로 시작 동작으로 만든다: 워크스페이스, 이름(선택), 모델, 첫 프롬프트를 받는다.

### 4. 오케스트레이션 대시보드

1. 현재 선택된 그룹의 Run 목록에서 하나를 고른다.
2. Run의 Task 목록(상태·제목·의존 관계)과 Worker 목록(상태·터미널 상태·주의 표시)이 보인다.
3. Worker를 선택하면 그 출력 일부를 읽는다.
4. 이 화면에서는 어떤 변경도 수행하지 않는다.
5. 실행이 없는 그룹은 선택 목록과 패널에 빈 상태를 보여준다.

### 5. 히스토리 브라우저

1. 현재 선택된 그룹의 최근 30일 세션 목록을 본다.
2. 검색어를 입력하면 선택한 그룹의 세션 본문에서 찾는다(30일 이전 포함).
3. 결과에서 세션을 열면 그 세션의 그룹으로 전환하고 채팅 화면으로 이동한다.
4. 저장된 검색 인덱스가 없으면 첫 검색에서 만든다. 진행률을 보여준다.
5. 각 세션 행은 펼쳐서 메시지 기록(시각·역할·본문)을 확인하고 접을 수 있다.

### 6. 프로젝트·워크트리 관리

1. 프로젝트 추가: 폴더 경로를 골라 Orca에 등록한다.
2. 그룹 생성: 프리셋(Feature·Loop·Manual)과 상관없이 그룹 이름, 부모 저장소, 모델, 첫 프롬프트를 받는다. 브랜치는 받지 않는다. 부모 저장소 기본값은 `C:\Users\DAESUNG\orca\workspaces\<그룹 이름 슬러그>` 이고, 이름을 입력하면 값이 따라 바뀌지만 사용자가 직접 고친 뒤에는 바뀌지 않는다. 생성하면 그룹 전체를 관리하는 허브 세션 1개만 만들고 워크트리는 만들지 않는다. 허브 세션은 워크트리에 속하지 않고 부모 저장소 폴더에서 시작한다. 슬러그가 빈 문자열이 되는 이름은 만들 수 없다. 프리셋별 첫 프롬프트 필수 여부와 생성 후 허브 동작은 [[30-specs/SPEC-hub-orchestration]]에서 확정한다.
3. 워크트리 생성: 레포지토리, 이름, 기본 브랜치를 받고, 필요하면 Pi 실행까지 함께 시작한다. 레포지토리는 등록된 목록(web·api·worker·infra·shared·docs)에서 고르며, 마지막으로 고른 값을 기억해 다음 생성의 기본값으로 쓴다.
4. 워크트리 불러오기: Orca 에 이미 있는 워크트리를 현재 그룹으로 가져온다. 레포지토리 필터와 `전체` 선택지를 주고, 다른 그룹에 속한 워크트리는 불러올 수 없다.
5. 하위 워크트리 생성: 부모 워크트리를 지정해 생성하고, 보드·오케스트레이션에서 계층을 확인한다. 부모 기본값은 `없음`(루트)이고, 허브 세션은 워크트리가 아니므로 부모 후보에 넣지 않는다. 새 워크트리의 폴더는 `<부모 저장소>\<워크트리 이름 슬러그>` 가 된다. 경로는 화면에 표시하지 않는다.
6. 이름·메타 수정: 표시 이름, 메모, 부모 저장소 경로를 바꾼다. 그룹 이름을 바꿔도 부모 저장소 값은 유지된다. 부모 저장소를 바꿔도 이미 만든 워크트리의 폴더 경로는 그대로이고, 새로 추가하는 워크트리만 새 부모 저장소 아래에 생긴다. 허브 세션은 워크트리가 아니므로 이 경로 규칙의 대상이 아니다.
7. 숨김: 목록에서 숨기거나 다시 보이게 한다. 삭제하지 않는다.
8. 삭제: 대상 이름과 미커밋 변경 여부를 보여주는 확인 대화상자를 거친 뒤에만 실행한다. 허브가 수행하는 워크트리·세션 삭제는 [[30-specs/SPEC-hub-orchestration]]의 자율 관리 규칙을 따르며 이 확인 대화상자를 거치지 않는다.

슬러그는 한글 음절을 로마자로 옮기고(받침 ㄹ 뒤의 ㄹ은 `l`, 받침 ㅇ은 항상 `ng`) 영문·숫자는 소문자로 유지하며 그 밖의 문자는 `-` 로 바꾼 뒤 연속 `-` 를 줄인다. 예: `고객 온보딩` → `gogaek-onboding`, `API 성능 루프` → `api-seongneung-rupeu`.

| CLI 성공 응답에 `ok:false` | 실패로 처리하고 `error.message` 노출 | "run_required: ..." 등 서버 메시지 |
| 세션 파일 파싱 실패(모르는 타입) | 해당 레코드만 건너뛰고 계속 | 없음(상세에 경고 1건 표시) |

| 세션 파일이 실행 중 계속 자라남 | 새 레코드를 이어 붙여 표시 | 없음 |
| 프롬프트 전송 대상이 종료됨 | 전송 실패, 재개 제안 | "세션이 종료되었습니다 — 재개할까요?" |
| 전송 후 응답 없음 | 전송 중 표시 유지, 중단 가능 | "전송 중..." |
| 검색 인덱스 생성 중 | 진행률 표시, 기존 목록은 계속 사용 | "세션 검색 준비 중 42%" |
| 워크트리 삭제 확인 요청 | 미커밋 변경 여부를 조회해 함께 표시 | "수정 3개가 남아 있습니다. 삭제할까요?" |
| 삭제 실행 실패 | 아무것도 제거되지 않았음을 명시 | "삭제하지 못했습니다: <사유>" |
| 빈 목록(해당 워크스페이스에 Pi 세션 없음) | 빈 상태 안내 + 새 세션 시작 버튼 | "이 워크스페이스에 Pi 세션이 없습니다" |

## 데이터

### 보여주는 것

| 데이터 | 출처 | 연결 기준 |
| --- | --- | --- |
| 세션 메타 | Pi 세션 헤더(JSONL) | 세션 ID = 파일명 접미사 |
| 메시지·도구 호출 | JSONL `message`/`toolResult`/`compaction` 레코드 | 세션 ID |
| 최근 도구 | JSONL `toolResult` 중 세션별 마지막 1건 | 세션 ID |
| 모델 변경 | JSONL `model_change` | 세션 ID |
| 워크스페이스·워크트리 | Orca `worktree list` / `project list` | 경로 |
| 실행 중 상태·터미널 | Orca `terminal list`, `worktree show` | 터미널 핸들, 워크트리 ID |
| 오케스트레이션 | Orca `run-list`, `task-list --run`, `worker-list`, `gate-list --run` | Run ID, Task ID, Dispatch ID |
| 프롬프트 전송 | Orca `terminal send` | 터미널 핸들 |

### 저장하는 것

- 사용자가 마지막으로 보던 워크스페이스와 화면.
- 세션 본문 검색 인덱스(세션 ID, 메시지 위치, 텍스트). 원본 세션 파일은 읽기만 하고 수정하지 않는다.
- 워크트리 그룹 정의(이름, 소속 워크트리, 순서, 부모 저장소 경로, 허브 세션 ID). 앱 로컬 설정으로만 저장하고 Orca 에는 쓰지 않는다.
- 인덱스는 앱 데이터 폴더의 SQLite 한 파일에 두고 FTS5 색인을 쓴다. 세션이 늘면 증분으로 갱신한다.

### 저장하지 않는 것

- Pi 세션 원본 수정·삭제.
- Orca 오케스트레이션 상태 변경.

## 미정사항

구현 전 확인 항목은 모두 닫혔다. 2026-11-22에 `orca agent launch --agent pi` 를 실행해 터미널 세션이 생성되는 것을 확인했다(근거와 명령: `docs/50-worklog/2026-11/2026-11-22.md`). `--surface chat` 으로 Pi가 뜨는지는 확인하지 않았고, 이 앱은 터미널 표면을 쓴다.

닫힌 항목과 결정 근거는 위 결정표에 있다.

## 완료 조건

- [ ] 앱을 실행하면 좌측 내비에 보드·채팅·오케스트레이션·히스토리가 보인다.
- [ ] Orca가 실행 중일 때 보드에 실행 중 Pi 세션이 노드로 나타나고, 세션 파일이 자라면 새 메시지가 열람에 반영된다.
- [ ] Orca를 끈 상태에서도 히스토리 목록과 채팅 열람이 되고, 제어 버튼이 비활성이며 상단에 안내 배너가 보인다.
- [ ] 노드를 선택하면 세션 상세(모델·시작 시각·마지막 활동·토큰)가 보인다.
- [ ] 보드에서 허브→직계 자식·부모-자식 세션·같은 워크트리·워크트리 상하위 관계가 각각 선으로 구분되고, 사이드바·채팅 목록·인스펙터에는 부모→자식 세션 계보가 트리로 보인다.
- [ ] 새 세션 시작을 실행하면 Orca에 PTY 세션이 생기고 보드에 나타난다.
- [ ] 채팅창에서 보낸 프롬프트가 실행 중 세션에 전달되고, 세션 파일에 user 메시지가 추가되어 화면에 반영된다.
- [ ] 오케스트레이션 화면에서 Run·Task·Worker·Gate가 조회되고 변경 버튼은 존재하지 않는다.
- [ ] 30일 이전 세션의 본문 내용으로 검색해도 결과가 나온다.
- [ ] 워크트리 삭제는 확인 대화상자 없이 실행되지 않고, 확인 후에는 Orca 목록에서 사라진다.
- [ ] Orca CLI 호출이 실패하면 배너가 뜨고 마지막 성공 값이 유지된다.
- [ ] 모르는 레코드 타입이 섞인 세션 파일도 열람되고, 경고 1건만 표시된다.
- [ ] 동시 20세션 상태에서 보드를 다시 그려도 끊김이 눈에 띄지 않는다.
- [ ] Orca에 없는 경로의 세션이 `외부` 라벨로 목록에 남고, 그 세션의 제어 버튼은 비활성이다.
- [ ] 사이드바에서 그룹을 고르면 보드가 그 그룹의 허브 세션과 워크트리만 그려지고, 다른 그룹을 골라도 선택한 그룹이 다시 열었을 때 유지된다.
- [ ] 사이드바에서 워크트리를 고르면 그 워크트리의 세션 계보가 항상 펼쳐진 트리로 보이고, 다른 워크트리를 골라도 접히지 않는다. 세션을 고르면 그 세션의 상세·인라인 채팅이 보드에 표시된다.
- [ ] 보드 최상단에 그룹 허브 세션이 전폭 카드로 보이고, 허브→루트 트렁크와 열 버스가 선으로 이어진다.
- [ ] 그룹을 만들면 허브 세션 1개만 생기고 워크트리는 0개다.
- [ ] 허브 세션을 제거하면 그룹 관리용 허브 세션이 새로 만들어져 최상단 카드로 다시 나타나고, 그 세션이 워크트리 열에 중복으로 그려지지 않는다.
