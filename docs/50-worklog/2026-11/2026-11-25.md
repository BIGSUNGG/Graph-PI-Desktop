### 1. 프리셋 지시 보강 (`src/main/preset.ts`)

허브가 단계를 건너뛰는 원인은 지시가 한 줄 요약이었기 때문이다. `PRESET_STEPS` 를 추가해 프리셋별 단계를 명시했다.

- feature: ① 답변 전 워크트리 생성 금지 ② 백엔드·프론트엔드 워크트리 각각 생성 후 `orca worktree list` 로 확인 ③ 프론트엔드가 목업 후보 3개를 만들고 선택을 질문 ④ `say` 를 **두 번** 호출해 프론트엔드·백엔드 세션에 각각 전달(같은 세션 중복 전송 금지)
- loop: ① 검토 축 분해 ② 6개 `loop` 레코드(프론트엔드·백엔드 × 성능·보안·아키텍처)마다 워크트리·세션 ③ 종료 시 허브가 통합 기록 ④ 다음 주기 배정
- manual: ① 첫 프롬프트를 Todo 로 옮긴다 ② 사용자 입력을 기다린다 ③ 입력 후에만 진행

핵심 구현 사실:

- `pi.cmd` 를 `cmd.exe /c` 로 부르면 인용이 깨지고 도구가 빠진다. `execFileSync(process.execPath, ['.../@earendil-works/pi-coding-agent/dist/bundle/cli.js', '-p', '--model', …, '--tools', 'bash', prompt])` 로 직접 실행하고 `-c` 로 세션을 이어간다.
- 허브가 만드는 워크트리는 임시 저장소 밖(`orca/workspaces/...`)에 생긴다. 경로 접두 비교 대신 `orca worktree list --json` 의 **실행 전후 id 차집합**으로 센다.
- 메시지 레코드 필드는 `fromSessionId`/`toSessionId` 다(`from`/`to` 아님). 잘못 읽으면 실제로는 성공한 실행을 실패로 판정한다.
- 질문에 답하는 방법은 앱과 동일하다. 같은 id 로 `status:"answered"` + `answer` 를 담은 레코드를 `seq` 를 올려 덧붙인다.

- 감사 계약: 기계 검사가 Windows 에서 shell 없이 `npm` 을 spawn 해 `spawn npm ENOENT` 로 fast-fail 했다(`spawnSync('npm',…,{shell:false})` 재현, `{shell:true}` 는 exit 0). 사용자 승인으로 검증 계약의 명령을 같은 동작의 shell-free 형태로 바꿨다: build → `node node_modules/electron-vite/bin/electron-vite.js build`, test → `node --test --test-reporter=spec "src/**/*.test.ts" "packages/harness/src/**/*.test.ts"`, e2e → `node node_modules/@playwright/test/cli.js test`, smoke → `node scripts/smoke-orca.mjs`, acceptance → `node scripts/check-acceptance.mjs`. 다섯 명령 모두 shell 없는 spawn 으로 exit 0 을 확인했다.

### 감사 기계 검사 Windows 차단 해소(도구 패치)

- 감사 fast-fail 은 `npm run build` 를 shell 없이 spawn 해 Windows 에서 `spawn npm ENOENT` 가 나는 GLLA 쪽 결함이었다. 검증 계약 문구를 shell-free `node …` 형태로 바꿔 봤지만, GLLA 가 계약을 메모리에서 다시 기록하면서 원래 문구로 되돌아가 유지되지 않았다(2026-11-25T06:41:38Z state 에 원래 문구 재기록 확인).
- 사용자 승인으로 전역 확장 `~/.pi/agent/npm/node_modules/pi-goal-list-loop-audit/extensions/goal-loop-shield.ts` 를 패치했다: win32 에서만 `spawn(cmdline, [], { shell: true })` 로 실행하고, 인자에 공백이 있으면 따옴표로 감싼다(`win32CommandLine`). 원본은 같은 폴더 `goal-loop-shield.ts.orig-win-fix` 로 백업했다.
- 검증: 같은 형태의 spawn(`npm run build`)이 exit 0. 확장 업데이트 시 되돌아갈 수 있으므로 재발하면 같은 패치를 다시 적용한다.
