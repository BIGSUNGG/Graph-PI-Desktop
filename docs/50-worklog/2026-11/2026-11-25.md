## 한 일

### 1. 프리셋 지시 보강 (`src/main/preset.ts`)

허브가 단계를 건너뛰는 원인은 지시가 한 줄 요약이었기 때문이다. `PRESET_STEPS` 를 추가해 프리셋별 단계를 명시했다.

- feature: ① 답변 전 워크트리 생성 금지 ② 백엔드·프론트엔드 워크트리 각각 생성 후 `orca worktree list` 로 확인 ③ 프론트엔드가 목업 후보 3개를 만들고 선택을 질문 ④ `say` 를 **두 번** 호출해 프론트엔드·백엔드 세션에 각각 전달(같은 세션 중복 전송 금지)
- loop: ① 검토 축 분해 ② 6개 `loop` 레코드(프론트엔드·백엔드 × 성능·보안·아키텍처)마다 워크트리·세션 ③ 종료 시 허브가 통합 기록 ④ 다음 주기 배정
- manual: ① 첫 프롬프트를 Todo 로 옮긴다 ② 사용자 입력을 기다린다 ③ 입력 후에만 진행

### 2. 재현 가능한 시나리오 하네스

| 스크립트 | 하는 일 |
| --- | --- |
| `scripts/scenario-hub.mjs` | 임시 git 저장소 + `groups.json`(preset feature) 준비 → 실제 `hubInitialPrompt` 로 프롬프트 생성 → `pi -p --model opencode-go/deepseek-v4.1-flash --tools bash` 1단계(질문만) → 앞선 질문 레코드를 `status:"answered"` 로 덧붙임 → `-c` 로 2단계(워크트리·목업 질문) → 3단계(`say` 중계) |
| `scripts/scenario-loop.mjs` | 같은 방식으로 preset loop 그룹을 만들어 6개 loop·워크트리·하위 Goal 생성 여부를 판정 |

핵심 구현 사실:

- `pi.cmd` 를 `cmd.exe /c` 로 부르면 인용이 깨지고 도구가 빠진다. `execFileSync(process.execPath, ['.../@earendil-works/pi-coding-agent/dist/bundle/cli.js', '-p', '--model', …, '--tools', 'bash', prompt])` 로 직접 실행하고 `-c` 로 세션을 이어간다.
- 허브가 만드는 워크트리는 임시 저장소 밖(`orca/workspaces/...`)에 생긴다. 경로 접두 비교 대신 `orca worktree list --json` 의 **실행 전후 id 차집합**으로 센다.
- 메시지 레코드 필드는 `fromSessionId`/`toSessionId` 다(`from`/`to` 아님). 잘못 읽으면 실제로는 성공한 실행을 실패로 판정한다.
- 질문에 답하는 방법은 앱과 동일하다. 같은 id 로 `status:"answered"` + `answer` 를 담은 레코드를 `seq` 를 올려 덧붙인다.
