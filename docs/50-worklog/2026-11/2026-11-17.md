## 목업 렌더러 멈춤 수정 (같은 날 추가)

### 증상·재현

`mock/index.html` 을 열면 브라우저 탭이 응답 없이 멈춘다. 재현·진단은 Chrome headless로 했다.

| 실행 | 결과 |
| --- | --- |
| `chrome --headless=new --disable-gpu --dump-dom` | 정상 (DOM 54KB) |
| `chrome --headless=new --enable-gpu --use-angle=swiftshader --dump-dom` | **멈춤** (20초 후 렌더러 강제 종료) |
| `chrome --headless=old --dump-dom` | **멈춤** |

GPU 경로에서만 재현되므로 사용자의 일반 브라우저와 같은 조건이다. (스크립트를 빼면 두 경로 모두 정상 → HTML/CSS는 원인 아님.)

### 근본 원인

`setSvg()` 가 DOMParser XML 문서의 자식 노드를 `while` 루프에서 `appendChild(document.importNode(child, true))` 로 **하나씩** 삽입하면 Chrome 렌더러가 멈춘다. 자식이 `<rect>` 1개뿐인 경우에도 멈췄다(원인 확정용 최소 재현). 같은 내용을 `innerHTML` 이나 `importNode(루트)+replaceChildren` 으로 넣으면 정상.

### 수정

```js
var root = document.importNode(doc.documentElement, true);
el.replaceChildren.apply(el, Array.prototype.slice.call(root.childNodes));
```

`mock/index.html` 의 `setSvg()` 본문만 교체했다. `innerHTML` 대입은 pi-lens 규칙 때문에 그대로 피했다.

| 스크린샷 1600×1000 | 사이드바 그룹 2개, 허브 카드 + 3레포 열, 칩이 카드 내부 |

미검증: 실제 GUI 창에서의 클릭 상호작용(그룹 전환·노드 선택)은 확인하지 않았다. headless 렌더 결과만 근거로 삼았다.

## fix 그룹 세로 트리 + 관계선 애니메이션

요구: `fix` 그룹에서 `develop` 이 가장 상위, 그 아래 하위 워크트리 2개. 각 관계선에 진행 방향 애니메이션을 넣어 어떤 작업이 흐르는지 보이게.

확정(사용자 선택): 세로 트리(develop 위 · 자식 2개 아래), 점선 흐름 + 이동 점 둘 다, 실행 중인 관계만 움직임, 부모 관계와 merge 화살표 유지.

데이터(`mock/mock-data.js`): `wt-fix-sec` · `wt-fix-perf` 에 `parent: "wt-develop"` 추가(스키마 신규 필드 없음, 그래프에만 쓰는 워크트리 트리 관계).

렌더(`mock/index.html`):

- `rowsOf(wid, skip, startY)` · `rowsEnd()` · `boardCols(wts, skip, top)` 로 분해하고, 자식 워크트리를 가진 워크트리를 root 로 뽑아 카드를 상단 전폭으로, 나머지는 그 아래 열로 배치했다(`childTop = root.y + root.h + 34`).
- 모든 관계선을 `edge(d, color, active, arrow)` 하나를 거쳐 그린다. `active` 면 클래스 `edge-flow`(점선 dash 흐름) + `edge-dot`(`<animateMotion>` + `<mpath href="#eN">`, 2.4s 무한 반복)을 붙인다.
- 애니메이션 조건은 `liveEdge(a, b) => a === "running" && b === "running"` — 양 끝이 모두 실행 중일 때만 움직인다.
- merge 는 root 가 있으면 위로 재라우팅: `M(자식 오른쪽) → +9 → lane(childTop-12) → develop 행 x → 행 위`. loop 원호도 같은 `edge()` 를 거쳐 점선 + 점이 된다.
- `@media (prefers-reduced-motion: reduce)` 에서 `.edge-flow` 의 dash 애니메이션을 끄고 `.edge-dot` 을 숨긴다.

검증(모두 headless, GUI 클릭 없음):

| 항목 | 결과 |
| --- | --- |
| `node mock/_check.js` | PASS — ids=50, sessions=10, worktrees=6, agents=5. 인라인 JS `new Function` 문법 검사 + `wt-develop` 단일 root · 자식 2개 · `.edge-flow`/`.edge-dot`/`prefers-reduced-motion` 존재 검사 추가 |
| 트리 좌표 | develop rect `x16 y16 w426 h94`, 자식 rect `y144` → 상위가 위 |
| merge 경로 | `M222 203 L231 203 L231 132 L36 132 L36 70` — 카드 아래 lane 으로 올라가 develop 행에서 끝, 클래스 없음(s-09 idle → 정적) |
| loop 경로 | `M250 199 A 8 8 0 1 1 262 189` + `class="edge-flow"` + `edge-dot`/`mpath#e4` |
| 움직임 실행 증거 | 가상시간 1200ms vs 2600ms 스크린샷 md5 `2a1b87…` / `75e931…` — 다름 |
| reduced-motion 증거 | `--force-prefers-reduced-motion` 에서 같은 두 시각 md5 `013a3554…` 동일 — 애니메이션 정지 |
| 오류 | `parsererror` 0, 콘솔 `Uncaught`/`SyntaxError` 0, 두 그룹 모두 exit 0 |
| g-login 회귀 | 허브 카드 `w646` + 3열 stub(`e1`~`e3`) 유지 |

알려진 한계: `fix` 그룹의 merge 화살표는 대상 `s-09` 가 `idle` 이라 규칙상 정적이고, 그 그룹에서 움직이는 것은 branch loop 뿐이다. `feature/login` 그룹은 허브·세 열이 모두 실행 중이라 stub 이 움직인다. 실제 창에서의 클릭(그룹 전환·노드 선택)은 여전히 미검증.

### 추가 디자인 피드백 반영

피드백: ① merge 화살표를 부모-자식 회색 방향표와 같은 위치로 ② loop 화살표 도착점도 동그란 노드 위에 ③ 부모-자식 세로 간격을 더 넓혀라.

반영:

- 세로 간격: 허브/루트와 자식 열 사이를 `+34` → `+64` 로 늘렸다(develop 하단 110 → 자식 상단 174, 허브 하단 68 → 열 상단 132).
- merge: 회색 커넥터 경로를 그대로 역방향으로 재사용한다. 회색이 `M119 126 L119 174` 이므로 merge 는 `M119 174 L119 126 L229 126 L229 110` — 자식 카드 상단 → 버스 → develop 카드 하단. 회색과 구분되도록 파란 점선(`.edge-dash`, `stroke-dasharray:6 5`)과 위쪽 화살표를 쓴다. 카드 사이 어중간한 위치에 있던 선은 제거됐다.
- loop: 각도 205°/335° 로 노드 반지름 5 위의 정확한 두 점을 계산해 호를 그린다(`M251.5 230.9 A 14 14 0 0 1 260.5 230.9`). 도착점이 노드 링 위에 닿고, 호 반지름을 8 → 14 로 키워 노드와 여유를 뒀다.

검증(같은 headless 방식): `node mock/_check.js` PASS, `#g-fix` 덤프에서 `e3` 경로가 위 값과 일치하며 `class="edge-dash"` `marker-end="url(#arw)"`, `e4` 끝점이 노드 원 위(r≈5), `parsererror` 0, 스크린샷 exit 0.

### 애니메이션 보강 (머지 · 루프)

피드백: 머지 방향표에도 애니메이션을 넣고, 루프는 점이 한 곳에 멈춘 것처럼 보이는 문제를 고쳐라.

반영:

- 머지: 움직임 조건을 `liveEdge(출발, 도착)` → `출발 세션 state === "running"` 으로 바꿨다. `s-07` 이 실행 중이면 `s-09`(idle) 로 향하는 merge 도 점선 흐름 + 경로를 따라가는 점(`mpath href="#e3"`, 2.4s)으로 움직인다. 즉 이전 “양 끝 실행” 규칙은 부모-자식 회색 커넥터에만 남는다.
- 루프: 짧은 호 + 별도 원 궤적 조합을 버리고 **하나의 경로**로 통일했다. 노드 중심 반지름 12 원호를 300°(`M253.9 244.8 A 12 12 0 1 1 265.2 240.7`)로 그리고 그 끝에 화살표를 붙인 뒤, 점은 같은 path(`mpath href="#l4"`)를 1.4s 주기로 돈다. 링이 노드를 둘러싸 '반복'으로 읽히고, 점은 링 위를 실제로 이동한다.
- reduced-motion 에서는 `edge-dot` 이 숨겨지고 `edge-flow` dash 애니메이션이 꺼진다.

검증(headless): `node mock/_check.js` PASS · `#g-fix` 덤프에 `edge-dot` 2개(머지 `mpath#e3`, 루프 `mpath#l4`) · 700ms vs 1100ms 스크린샷 md5 다름(움직임) · `--force-prefers-reduced-motion` 에서 같은 두 시각 md5 동일(정지) · `feature/login` 덤프 `parsererror` 0, 허브 stub 3개 각각 점 표시.

### 애니메이션 시안 선택(N1 · M2 · L1) 적용 — 현재 기준

사용자 요청으로 `mock/animations.html` 에 카테고리별 4종씩 12개 시안을 만들고, 사용자가 **N1 확산 링 · M2 꼬리 혜성 · L1 회전 링**을 선택했다. 아래 값이 현재 `mock/index.html` 의 기준이며, 위 “추가 디자인 피드백 반영”·“애니메이션 보강” 절의 loop/머지 서술은 이 절로 대체된다.

- 노드(N1): `s.state === "running" && !s.loop` 인 세션에 `circle.node-ring`(r 5→11, 2s, `ring-out`). 루프 세션은 링과 겹치지 않도록 제외.
- 머지(M2): `edge(..., comet=true)` 가 `stroke-dasharray` 대신 `class="edge-flow"` + 점 3개(`edge-dot`, begin 0/−0.25s/−0.5s, 2.4s). 출발 세션이 running 이면 움직인다(사용자 요청으로 "양 끝 실행" 규칙에서 변경).
- 루프(L1): 점선 원(`r=14`, `stroke-dasharray="4 4"`, `class="loop-ring"`)이 `dashoffset -22 / 1s` 로 회전. 이동 점은 제거.
- 부모-자식 트렁크도 `edge()` 를 거치도록 바꿔 같은 규칙을 따른다(`trunkLive = topLive && 자식 중 실행 중`). g-login 은 허브와 자식이 모두 running 이라 트렁크·stub 5개가 모두 움직이고, g-fix 는 develop 세션이 idle 이라 트렁크가 정적이다.

검증: `node mock/_check.js` PASS · g-fix 덤프 `edge-flow` 1 / `edge-dot` 3 / `loop-ring` 1 / `node-ring` 1 / parsererror 0 · g-login 덤프 `edge-flow` 5 / `edge-dot` 5 · 700ms vs 1500ms 캡처 md5 다름 · `--force-prefers-reduced-motion` 두 시각 md5 동일 · 스크린샷 1600×1000 exit 0.

## 애니메이션 전체 시안 갤러리

기존 갤러리는 노드·머지·루프 12종만 있었고, 나머지 화면 요소는 애니메이션이 없었다. 적용 가능한 항목을 전부 모은 별도 갤러리를 만든다.

| 파일 | 내용 |
| --- | --- |
| `mock/animations-full.html` | 11개 카테고리 × 3종 = 33 시안, 카테고리별 radio 선택, footer 에 선택 요약 + 복사 버튼 |

카테고리: ①세션 노드 상태 ②부모-자식 연결선 ③머지 ④루프 ⑤워크트리 카드 ⑥사이드바 ⑦상세 인스펙터 ⑧채팅 ⑨오케스트레이션 ⑩히스토리 ⑪화면 전환·토스트·다이얼로그. ⑤~⑪은 현재 목업에 애니메이션이 없는 요소다.

검증: 헤드리스 `--dump-dom` exit 0, cards 33 · radios 33 · categories 11 · stage 33 · `parsererror` 없음 · `innerHTML` 0. 선택 동작은 임시 사본에서 radio 3개를 dispatch 해 `pick=node=N1 · chat=T1 · shell=V1`, `is-on` 3개 확인 후 삭제. 스크린샷 1600×2600 에 11개 섹션 전부 표시.

미검증: 실제 브라우저에서 마우스로 선택·복사하는 동작, `prefers-reduced-motion` 에서의 모습(갤러리는 정지 규칙만 넣고 별도 캡처하지 않음).

## 애니메이션 적용 (사용자 선택 결과)

카테고리별로 질문해 사용자가 고른 조합을 `mock/index.html` 에 적용했다. 모두 CSS 키프레임 + 소량의 JS 훅으로 구현했고 새 라이브러리는 쓰지 않았다.

| 항목 | 선택 | 구현 |
| --- | --- | --- |
| 노드 | 확산 링 | 그대로 유지(`node-ring`, ring-out 2s) |
| 부모-자식 연결선 | 점선 흐름만 | `edge()` 에서 `dots` 인자를 0으로 두어 이동 점 제거(E1). 트렁크·stub 은 흐름만 남음 |
| 머지 | 점선 흐름 + 점 1개, 주황 | `edge(..., "#d4a300", moving, "arwl", true, 1)`, 라벨도 주황 |
| 루프 | 회전 링 | 그대로 유지(`loop-ring`, 1s) |
| 카드 | 셋 다 | 선택 테두리 맥동(`.wt-card.is-sel`), 호버 리프트(`.wt-col:hover .wt-card`), dirty 점멸(`.dirty-dot`) |
| 사이드바 | 셋 다 | 펼침 행 순차 등장(`.grp.is-open-anim`), 선택 행 좌측 선 스윞(`.wt-row.is-sel::before`), 새 그룹 헤더 플래시(`.grp.is-flash`) |

| 채팅 | 셋 다 | 전송 직후 타이핑 점 말풍선, 새 메시지 플래시(`.is-new`), 도착 시 응답 메시지도 플래시 |
