## 레포지토리 선택 (첫 번째 작업)

### 목표

`워크트리 추가` 팝업에 레포지토리 선택 요소를 넣는다. 사용자가 고른 레포지토리가 새 워크트리의 `repo` 값이 되고, `기존 불러오기` 탭에서는 같은 선택 요소가 후보 목록의 필터로 동작한다. 그룹이 여러 레포지토리를 함께 담는 구조는 유지한다.

### 확정한 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| "프로젝트"의 의미 | 레포지토리(web·api·worker·infra·shared·docs) | 사용자 정정. Server·Client·Contract처럼 나뉜 레포를 한 그룹에서 통합해 작업하는 것이 제품 핵심 |
| 라벨 | `레포지토리` | 카드의 `repo` 값과 같은 것임을 드러낸다. 기존 그룹 생성의 `부모 저장소`는 경로 값을 받는 별개 필드라 그대로 둠 |
| 선택지 | 데이터에 등장하는 6개 | `MOCK.repos` 한 곳에서 관리. 불러오기 후보 `wt-orca-docs`(repo `docs`)까지 목록과 일치 |
| 불러오기 탭 | 필터 + `전체` 선택지 | 다른 레포 후보를 계속 불러올 수 있어야 그룹 통합 원칙이 깨지지 않는다 |
| 기본값 | 직전 선택 기억(`state.repo`) | 사용자 선택. 불러오기 필터도 같은 값으로 시작 |

- 이름이 다르어도 슬러그가 같으면(`결제 화면`·`결제  화면`) 같은 폴더 경로가 된다. 지금은 막지 않는다.
- 그룹 편집으로 부모 저장소를 바꾸면 기존 워크트리·허브 폴더 경로는 그대로고 새 워크트리만 새 경로를 쓴다(SPEC §6.6에 명시). 실제 Orca 폴더가 이동하지 않는 것을 따른 모델링이다.
- 슬러그 함수는 `mock/mock-data.js`에 두었다. `mock/_check.js`가 Node에서 그대로 호출해 검사하려면 데이터 파일에 있어야 해서, 설계 당시의 "index.html" 위치에서 옮겼다.

## 사이드바 하위 세션 펼침 (네 번째 작업)

### 목표

왼쪽 사이드바에서 워크트리를 고르면 그 워크트리의 세션 목록이 아래로 펼쳐지고, 세션을 고르면 그 세션을 바로 선택한다.

### 승인본 기준 (정정 후 구현)

| 항목 | 승인본 |
| --- | --- |
| 펼침 트리거 | 워크트리 행 클릭 = 그 워크트리 선택 + 펼침. 같은 행을 다시 클릭하면 목록만 접히고 워크트리 선택은 유지 |

## 허브 = 그룹 관리 세션 (다섯 번째 작업)

### 목표

허브를 "그룹 전체를 관리하는 세션"으로 재정의하고, 그룹 생성·보드 배치·클릭·삭제 동작을 그 정의에 맞춘다. 코드 변경은 이 절을 쓰기 전에 승인·구현·검증이 끝났고, 이 절은 그 결과와 문서 반영을 기록한다.

### 확정한 결정

| 항목 | 결정 |
| --- | --- |
| 허브 정의 | 그룹 전체를 관리하는 세션. 워크트리가 아니며 실행 위치는 부모 저장소 폴더 |
| 보드 최상단 | 그룹 허브 세션 카드. 그 아래 루트 워크트리, 다시 그 아래 하위 열 |
| 그룹 생성 | 허브 세션만 만든다. 워크트리 0개, 브랜치 선택 없음 |
| 그룹 행 클릭 | 비활성 그룹 행 = 그룹 선택 + 허브 세션 선택, 이미 활성인 그룹 행 = 접기·펴기 |
| 허브 세션 삭제 | 그룹 관리용 허브 세션을 새로 만든다(워크트리 없음, 첫 프롬프트 없음). 승계 방식은 보드에서 허브가 워크트리 열과 중복으로 보여 사용자가 기각 |
| 재생성 허브 모델 | 지운 허브의 모델을 그대로 쓴다 |
| 삭제 후 선택 | 새로 만든 허브 세션을 선택한다(전역 첫 활성 세션으로 튀지 않게) |
| 삭제 확인 문구 | 허브 세션이면 "그룹 관리용 허브 세션이 새로 만들어집니다" 안내를 보여준다 |

### 남은 것

- 허브 세션을 지우면 그룹 관리용 세션이 새로 생기므로, 연속 삭제하면 빈 관리 세션이 누적된다(시드 데이터에는 영향 없음).
- 허브가 아닌 세션을 지우면 선택이 전역 첫 활성 세션으로 튀어 다른 그룹 세션 상세가 보일 수 있다(이번 범위 밖 기존 동작).
- 보드에 허브가 없는 상태는 이제 삭제 경로로는 만들어지지 않는다(데이터를 직접 고칠 때만).

- `mock/_evidence/` 는 `.gitignore` 대상이라 위 probe·스크린샷은 커밋되지 않는다. 보드 배치·클릭·허브 재생성을 막는 커밋된 테스트는 없고 `mock/_check.js` 는 정적 문자열·데이터 불변식 검사다.
- `mock/_check.js` 에는 `hubOf`·`hubStart`·`hubWtOf`·`허브로 지정` 이 다시 들어오는지 보는 검사가 없다. 삭제는 코드 대조로만 확인했다.
