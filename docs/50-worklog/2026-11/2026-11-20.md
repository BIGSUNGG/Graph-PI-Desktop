# 2026-11-20 작업 기록

- 날짜: 2026-11-20

## 목표

`워크트리 추가` 팝업에 레포지토리 선택 요소를 넣는다. 사용자가 고른 레포지토리가 새 워크트리의 `repo` 값이 되고, `기존 불러오기` 탭에서는 같은 선택 요소가 후보 목록의 필터로 동작한다. 그룹이 여러 레포지토리를 함께 담는 구조는 유지한다.

## 확정한 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| "프로젝트"의 의미 | 레포지토리(web·api·worker·infra·shared·docs) | 사용자 정정. Server·Client·Contract처럼 나뉜 레포를 한 그룹에서 통합해 작업하는 것이 제품 핵심 |
| 라벨 | `레포지토리` | 카드의 `repo` 값과 같은 것임을 드러낸다. 기존 그룹 생성의 `부모 저장소`는 경로 값을 받는 별개 필드라 그대로 둠 |
| 선택지 | 데이터에 등장하는 6개 | `MOCK.repos` 한 곳에서 관리. 불러오기 후보 `wt-orca-docs`(repo `docs`)까지 목록과 일치 |
| 불러오기 탭 | 필터 + `전체` 선택지 | 다른 레포 후보를 계속 불러올 수 있어야 그룹 통합 원칙이 깨지지 않는다 |
| 기본값 | 직전 선택 기억(`state.repo`) | 사용자 선택. 불러오기 필터도 같은 값으로 시작 |
| 표기 | `repo · branch` 유지 | 이번 요청 범위 밖 |

## 남은 것

- 불러오기 필터 결과가 0건일 때 `불러올 워크트리가 없습니다.`만 보여서 `전체`에 후보가 있다는 사실을 알 수 없다. 문구 변경은 UX 결정이라 이번 범위에서 제외했다.
- 불러오기 필터를 바꾸면 `state.repo`(생성 기본값)도 함께 바뀐다. "직전 선택 기억"의 자연스러운 해석으로 판단해 유지했지만, 사용자가 원하지 않으면 한 줄로 분리할 수 있다.
- 그룹 생성 팝업의 `부모 저장소`는 여전히 경로(`M.repo`)를 저장하고, 그룹 허브 워크트리의 `repo`도 그 경로가 된다. 이번 범위에서 동결했으므로 `_check.js`의 레포 검사는 시드 데이터로 한정했다.
- `mock/_evidence/shot-dialogs.mjs`의 Loop 단계는 `[data-act="wt-loop"]`가 사라진 뒤 고쳐지지 않은 상태다.
- [[50-worklog/2026-11/2026-11-19]] 의 측정값(워크트리 추가 필드 6, 불러오기 행 5)은 그날 기준 기록이라 지금 목업(필드 7, 기본 필터 1행)과 다르다. 과거 기록은 고치지 않고 이 문서를 최신 값으로 둔다.
