## 레포지토리 선택 (첫 번째 작업)

### 목표

`워크트리 추가` 팝업에 레포지토리 선택 요소를 넣는다. 사용자가 고른 레포지토리가 새 워크트리의 `repo` 값이 되고, `기존 불러오기` 탭에서는 같은 선택 요소가 후보 목록의 필터로 동작한다. 그룹이 여러 레포지토리를 함께 담는 구조는 유지한다.

### 확정한 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| "프로젝트"의 의미 | 레포지토리(web·api·worker·infra·shared·docs) | 사용자 정정. Server·Client·Contract처럼 나뉜 레포를 한 그룹에서 통합해 작업하는 것이 제품 핵심 |
| 라벨 | `레포지토리` | 카드의 `repo` 값과 같은 것임을 드러낸다. 기존 그룹 생성의 `부모 저장소`는 경로 값을 받는 별개 필드라 그대로 둠 |
| 선택지 | 데이터에 등장하는 6개 | `MOCK.repos` 한 곳에서 관리. 불러오기 후보 `wt-orca-docs`(repo `docs`)까지 목록과 일치 |

- 이름이 다르어도 슬러그가 같으면(`결제 화면`·`결제  화면`) 같은 폴더 경로가 된다. 지금은 막지 않는다.
- 그룹 편집으로 부모 저장소를 바꾸면 기존 워크트리·허브 폴더 경로는 그대로고 새 워크트리만 새 경로를 쓴다(SPEC §6.6에 명시). 실제 Orca 폴더가 이동하지 않는 것을 따른 모델링이다.
- 슬러그 함수는 `mock/mock-data.js`에 두었다. `mock/_check.js`가 Node에서 그대로 호출해 검사하려면 데이터 파일에 있어야 해서, 설계 당시의 "index.html" 위치에서 옮겼다.

## 사이드바 하위 세션 펼침 (네 번째 작업)

### 목표

| 항목 | 승인본 |

## 허브 = 그룹 관리 세션 (다섯 번째 작업)

### 목표

허브를 "그룹 전체를 관리하는 세션"으로 재정의하고, 그룹 생성·보드 배치·클릭·삭제 동작을 그 정의에 맞춘다. 코드 변경은 이 절을 쓰기 전에 승인·구현·검증이 끝났고, 이 절은 그 결과와 문서 반영을 기록한다.

### 확정한 결정

| 항목 | 결정 |
| --- | --- |
| 허브 정의 | 그룹 전체를 관리하는 세션. 워크트리가 아니며 실행 위치는 부모 저장소 폴더 |
| 보드 최상단 | 그룹 허브 세션 카드. 그 아래 루트 워크트리, 다시 그 아래 하위 열 |
| 그룹 생성 | 허브 세션만 만든다. 워크트리 0개, 브랜치 선택 없음 |
| 그룹 행 클릭 | 비활성 그룹 행 = 그룹 선택 + 허브 세션 선택, 이미 활성인 그룹 행 = 접기·펴기 |
| 허브 세션 삭제 | 그룹 관리용 허브 세션을 새로 만든다(워크트리 없음, 첫 프롬프트 없음). 승계 방식은 보드에서 허브가 워크트리 열과 중복으로 보여 사용자가 기각 |
| 재생성 허브 모델 | 지운 허브의 모델을 그대로 쓴다 |
| 삭제 후 선택 | 새로 만든 허브 세션을 선택한다(전역 첫 활성 세션으로 튀지 않게) |
| 삭제 확인 문구 | 허브 세션이면 "그룹 관리용 허브 세션이 새로 만들어집니다" 안내를 보여준다 |

## Goal·List·Loop·Audit 기획 (아홉 번째 작업)

이 절의 수치가 현재 기준이다. 여덟 번째 절의 18행·19행·14건·21개는 그 작업 당시 값이다.

### 목표

기존 허브 오케스트레이션 SPEC에 Pi 하네스의 Goal·List·Loop·Audit을 추가하고, ADE 인스펙터 4탭과 보드 4슬롯 배지로 시각화하는 규칙을 확정한다. GLLA와 거의 같은 패키지를 새로 구현하되 기존 GLLA 패키지를 연동하지 않는다. 코드·목업은 바꾸지 않는다.

### 확정한 결정 (사용자 답변)

| 항목 | 결정 |
| --- | --- |
| 구현 위치 | 새 Pi 하네스 패키지에 직접 구현. GLLA는 개념 참고이며 연동하지 않는다 |
| Goal 소유 | 세션 단위. 모든 작업 세션은 활성 Goal 1개와 대기 Goal 큐를 가진다. 허브는 최상위 Goal 1개와 List를 가진다 |
| Goal과 TODO | 별도 개념. Goal은 완료 조건을 가진 결과, TODO는 실행 작업 목록. 자동 동기화하지 않는다 |
| Goal 상태 | `active`·`auditing`·`complete`·`paused`·`aborted`. `complete`는 Audit 승인으로만 된다 |
| 완료 조건 | 1개 이상. 각 조건은 증거와 함께 Audit에서 통과/실패를 판정하고, 조건이 바뀌면 revision을 올린다 |
| List | 세션별 Goal 큐. 세션 List 항목은 Goal이고, 승인 후 다음 항목을 자동 활성화한다. `aborted`는 자동 진행하지 않는다. 허브 List 항목은 별도 규칙을 따른다 |
| 허브 List | 오케스트레이션 큐. 항목 자체는 Goal이 아니며, 한 항목을 여러 하위 세션에 fan-out하고, 현재 항목의 유효 하위 Goal이 모두 승인되어야 다음 항목을 배정한다. 대체되지 않은 `aborted`가 있으면 차단한다 |
| 부모 링크 | 하위 Goal이 허브 List 항목 ID를 저장하고, 허브 Audit이 하위 verdict를 롤업한다 |
| 허브 감독 | 허브도 Goal·List·Loop·Audit을 갖고, 직접 구현이 아니라 하위 세션 Goal을 오케스트레이션해 완료한다 |
| Loop | Goal 하나를 측정값 또는 Audit 기준으로 반복한다. 측정값은 선택이고, 없으면 Audit 승인과 상한으로 끝낸다 |
| Audit 주체 | 완료 주장 시 작업 세션과 분리된 새 Audit 세션이 수행한다 |
| Audit 범위 | 대상과 같은 워크트리를 읽기 전용으로 검사한다. 쓰기 도구는 비활성이다 |
| Audit 결과 | `approved`→완료, `rejected`→active+실패 조건, `impossible`→aborted, `error`→paused |
| Audit 표시 | 보드·사이드바에 임시 Audit 카드, verdict 후 이력으로 이동. 최신 결과+이력+아카이브 |
| 아카이브 | 완료·중단 Goal과 Audit 이력을 모두 보관하고 그룹 단위로 조회한다. 세션 삭제 후에도 유지한다 |
| 인스펙터 | Goal·List·Loop·Audit 4탭. 그룹은 허브 4탭+하위 집계, 세션은 그 세션 4탭. 감독 탭은 읽기 전용이고 채팅 입력은 유지한다 |
| 보드 배지 | 4슬롯 고정. 강조는 감사 거부·불가능·오류 > 일시정지·차단 > 질문 대기 > 진행·감사 중 > 완료 > idle |
| Run 용어 | 기존 오케스트레이션 Run의 `goal`은 화면에서 `목적`으로 표기한다 |
| 사용자 제어 | Goal·List·Loop·Audit 조작은 앱에서 읽기 전용이다. 시작·중지·재시도·재배정·검증은 Pi 채팅이나 에이전트 도구로 한다. 앱에 감독 조작 버튼을 두지 않는다 |

### 설계 해석 (Advisor 보완)

사용자 답변만으로는 완료 판정이 모순되는 지점을 다음처럼 풀었다. 새 제품 결정이 아니라 구현 가능한 최소 규칙이며, SPEC의 `설계 해석` 절과 같다.

| 항목 | 해석 |
| --- | --- |
| 허브 List 항목 | Goal이 아니다. 허브 Goal 하나가 List 전체를 소유하고, 항목은 그 아래 작업 묶음이다. 세션 List 항목만 Goal이다 |
| 허브 Audit | 롤업 감사. 하위 코드를 다시 감사하지 않고 하위 verdict·증거 요약·통합 기록·원래 목표 매핑을 검사한다. 하위 승인이 빠지면 허브 Goal을 승인하지 않는다 |
| 허브 항목 완료 | `childGoalIds`를 배정 완료 시점에 고정한다. 재시도는 새 Goal로 대체하고 이전 Goal을 `supersededByGoalId`로 뺀다. 하위 Goal 0개는 완료 불가. 완료 후 revision 변경은 완료를 되돌리지 않는다 |
| Loop 상태 | 측정 목표 달성·감사 대기는 `paused`(`pauseKind=audit`), 상한·불가능·사용자 중지는 `stopped`다. 상한이면 Goal도 `paused`(`loop_bounds`)로 둔다 |
| 감사 중 변경 | Goal이 `auditing`이면 소유 세션은 새 작업을 시작하지 않는다. Audit은 시작 커밋을 고정하고, 워크트리가 바뀌면 verdict 없이 `error`로 끝낸다 |
| Audit 명령 | 소스·설정·의존성 수정은 금지하지만 테스트·측정 명령은 실행할 수 있다. 산출물은 증거로만 쓰고 커밋하지 않는다 |
| 허브 Audit 거부 | 보완 항목을 허브 List에 만들고 계속한다. 허브 Goal 불가능은 그룹 차단으로 표시한다 |
| paused 사유 | `user`·`agent`·`audit_error`·`question`·`loop_bounds`·`dependency`·`standby`를 Goal에 남기고 앱에 표시한다 |
