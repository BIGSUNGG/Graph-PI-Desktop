## MVP 구현 (전자 앱 + Pi 하네스)

목표: `docs/30-specs/SPEC-graph-pi-ade.md`·`SPEC-hub-orchestration.md` 의 MVP 를 실제 Electron 앱과 Pi 하네스로 완성한다. UI/UX 는 `mock/index.html` 과 동일해야 하고, 목업에 없는 부분은 Orca 디자인 철학을 따른다. 구현은 PI-Crew 워커가 기능별로 나눠 맡고, 부모 세션은 조율·검증만 한다.

### 결정

- 레포 구조는 [[20-decisions/ADR-0007-electron-mock-parity-app]] — 앱은 Electron(루트), 하네스는 `packages/harness`, 공통 타입은 `src/shared/contract/` 단일 계약.
- 상태 저장은 두 축이다. 앱 데이터(`groups.json`, `settings.json`, `index.sqlite`)는 `~/.graph-pi/data/`(`GRAPH_PI_DATA_DIR` 로 덮어쓰기), 하네스 상태는 `<dataDir>/groups/<groupId>/state.jsonl` append-only JSONL. Pi 세션은 여전히 Pi 가 쓰는 JSONL 을 읽기 전용으로 소비한다([[20-decisions/ADR-0002-pi-session-jsonl-data-source]]).
- Pi 에이전트가 하네스 상태를 바꾸는 유일한 통로는 CLI(`node packages/harness/src/cli.ts`)다. Pi 도구 표면은 아직 없고, bash 로 CLI 를 호출하는 경로를 MVP 로 본다.

### 실행 증거 (통합 스모크·스크린샷)

가장 중요한 수정은 보드 노드가 모델·토큰을 못 보여주던 버그였다. `createPiService().sessions()` 는 `groupSessions` 메타데이터만 쓰므로 `model: null`, `usage 0` 이 나왔다. `src/main/pi/stats.ts` 를 새로 만들어 JSONL 의 `type:'message'` 레코드에서 `message.model` 과 `message.usage` 를 합산하고, `src/main/pi/index.ts` 에 mtime 키 캐시(`statsCache`)를 두어 매 스캔 전체 파싱을 피했다.

`npm run smoke:integration`(`scripts/smoke-integration.mjs`)은 진짜 임시 저장소 → `orca repo add` → `worktree create` → 그 워크트리 안에서 `pi -p` 실행 → 앱 계약 계층으로 세션 노드 조회 → `terminal close` → `worktree rm --force` 순서를 돈다. 결과: `smoke-integration PASS (steps=11, failed=0, terminalClosed=true)`. 이때 관측값은 `model=deepseek-v4.1-flash`, `usage input=8208 output=3`, `messages=2` 였다.

경로 비교에서 두 번 틀렸다. Orca 는 `C:/…` 를, 세션 헤더는 `C:\…` 를 주므로 구분자를 정규화해야 하고(`norm = value.split(sep).join('/').toLowerCase()`), Windows 에서 `execFileSync('pi', …, {shell:true})` 는 `cwd` 를 무시한다(`cmd.exe /c pi …` 로 감쌌다). 워크트리 삭제는 방금 끝난 프로세스의 핸들 때문에 잠겨서 `--force` 와 3회 재시도로 풀었다.

화면 산출물: `node scripts/capture-screens.mjs` 가 임시 데이터 디렉터리에 그룹·Goal·List·Loop·TODO·Audit 를 CLI 로 심고 실제 Pi 세션을 만든 뒤 Electron 을 띄워 `mock/_evidence/{view-board,view-chat,view-orchestration,view-history,inspector-goal,inspector-list}.png` 를 남겼다. `_evidence/` 는 gitignore 대상이므로 로컬 검증용이다.

타입 설정도 한 번 더 정리했다. `src/preload/index.d.ts` 는 `index.ts` 에 가려져 선언이 적용되지 않아 `window.api` 가 없다는 오류가 났고, `src/global.d.ts` 로 옮겼다(`api?: GraphPiApi`). `tsconfig.web.json` include 도 `src/global.d.ts` 로 바꿨다. 이제 editor/lens 가 쓰는 루트 `tsconfig.json` 을 포함해 네 설정 모두 `tsc -p … --noEmit` exit 0 이다.

주의: pi-lens 는 여전히 `ts:5097`(allowImportingTsExtensions)과 존재하는 문서 링크를 오류로 보고한다. 네 tsconfig 모두 해당 플래그가 켜져 있고 `npx tsc` 가 전부 0 이므로 도구 쪽 문제로 판단했다.

## 보드를 실제로 그리게 만든 다섯 버그와 수용기준 8건 추가 구현

### 왜

E2E 두 건이 "요소를 찾지 못함"으로 실패했는데, 원인은 테스트가 아니라 제품 코드였다. 보드에 세션이 한 번도 그려진 적이 없었다.

### 고친 버그

1. `src/main/state/groups.ts` — `groups.json` 을 시작 시 읽지 않았다. `list()/get()` 은 동기 API 인데 캐시는 비동기 `read()` 로만 채워져서, 새 앱은 그룹이 0개였다. 생성 시점 동기 로드(`readFileSync`)로 고쳤다.
2. `src/main/ipc.ts` `rootsOf` 가 그룹 폴더를 빼서 허브 세션이 아예 로드되지 않았다.
3. 새 데이터 디렉터리에서 `settings.lastGroupId` 가 비어 그룹 선택이 없었다 → `AppStatus.groups: GroupSummary[]` 를 계약에 추가하고, 스토어가 첫 그룹을 자동 선택한다.
4. `src/main/pi/index.ts` 가 `groupSessions` 에 `groupId` 를 넘기지 않아 `lineage.ts` 가 `groupId` 자리에 **경로**를 채웠다. 렌더러는 `session.groupId === activeGroup.id` 로 거르므로 어떤 빌드에서도 세션이 보이지 않았다.
