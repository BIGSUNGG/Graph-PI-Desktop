# ADR-0002 Pi 대화 데이터는 세션 JSONL 직접 파싱과 Orca CLI를 함께 쓴다

- 상태: active
- 날짜: 2026-11-17

## 맥락 (Context)

ADE는 세 가지 다른 종류의 데이터를 동시에 다룬다.

1. 대화 내용·도구 호출 — Pi 세션 JSONL에만 존재한다.
2. 실행 상태·워크트리·터미널 — Orca만 알고 있다.
3. 오케스트레이션 Run·Task·Worker — Orca 오케스트레이션 상태에만 있다.

Orca CLI만으로는 1번을 얻을 수 없고, JSONL만으로는 2·3번을 얻을 수 없다. 근거는 [[orca-cli-and-pi-sessions]] 에 정리했다.

## 결정 (Decision)

**하이브리드**로 간다. 대화·도구 호출은 Pi 세션 JSONL을 직접 파싱하고, 프로세스·워크트리·터미널·오케스트레이션 제어는 Orca CLI(`--json`)로 수행한다. 두 출처는 세션 ID(JSONL 파일명의 접미사)와 워크트리 경로를 기준으로 연결한다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 | 선택 여부 |
| --- | --- | --- | --- |
| Orca API·CLI만 | 유지보수 최소, Orca 내부 변경에 안전 | 대화 본문 접근 불가. 채팅·히스토리 화면 구현 불가 | 제외 |
| Pi JSONL만 | Orca 의존 없음, 오프라인 열람 | 실행 중 상태·워크트리·오케스트레이션 정보 없음. 제어 불가 | 제외 |
| 하이브리드 | 모든 화면 구현 가능, 부분 실패 시에도 열람 유지 | 두 출처 정합성 처리 필요, Pi 포맷 변경 추적 필요 | **선택** |

## 결과 (Consequences)

- 장점: Orca가 꺼져 있어도 세션 열람은 동작한다. Orca 쪽 데이터가 늦게 갱신되어도 대화 화면은 즉시 최신이다.
- 단점: 세션 ID와 경로가 어긋나는 경우(워크트리 경로 변경, 프로젝트 이동, 삭제된 폴더)의 표시 규칙이 필요하다. Pi 세션 포맷 v3은 공개 계약이 아니므로 파싱 계층이 버전을 확인하고 모르는 레코드를 무시해야 한다.
- 되돌리기 비용: JSONL 파싱 계층을 걷어내면 채팅·그래프·본문 검색을 잃는다. Orca 어댑터를 걷어내면 실시간 상태·제어를 잃는다. 두 계층 모두 화면과 분리되어 있어 각각 교체는 가능하다.

## 후속 작업

- 세션 ID ↔ 워크트리 경로 불일치 시 표시 규칙을 설계에서 정한다.
- 본문 검색 인덱스의 저장 위치·형식·갱신 전략은 설계 단계에서 정한다.
- Pi 세션 포맷 버전 확인 실패 시 동작(열람 중단과 안내)을 설계에서 정한다.
