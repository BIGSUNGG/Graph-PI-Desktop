# ADR-0001 ADE를 Orca 플러그인이 아닌 별도 데스크톱 앱으로 만든다

- 상태: active
- 날짜: 2026-11-17

## 맥락 (Context)

Pi 전용 ADE가 필요하다는 요청에서 출발했다. 요구 화면은 네 가지다: 상태 보드·그래프, 자체 채팅 UI, 오케스트레이션 대시보드, 세션 히스토리 브라우저.

로컬 Orca 1.4.259에는 플러그인 체계가 있고(호스트 API major 1 고정, 패널·커맨드·이벤트·훅 제공) 설치본에서 바로 쓸 수 있다. 그러나 호스트 API에는 **대화 내용을 읽는 메서드가 없다**. `agent.listSessions` 는 제목·시각·메시지 수·토큰 수만 주고 본문과 파일 경로는 주지 않는다. 플러그인 패널은 샌드박스 프레임이라 네트워크가 닫혀 있고 `terminal.sendText` 는 워커 전용이다.

따라서 자체 채팅 UI와 히스토리 본문 열람은 플러그인 경로에서 영구히 불가능하다. 근거는 [[orca-cli-and-pi-sessions#Orca 플러그인 호스트 API 제약 (경로 선택의 근거)]] 에 있다.

## 결정 (Decision)

ADE를 **Orca와 독립된 별도 데스크톱 앱**으로 만든다. Orca는 엔진으로만 사용한다(워크트리·터미널·에이전트·오케스트레이션 제어). 화면과 데이터 모델은 새 앱이 소유한다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 | 선택 여부 |
| --- | --- | --- | --- |
| Orca 플러그인 | 설치·업데이트가 자동, Orca UI와 한 창, 권한 모델 제공 | 대화 읽기 API 부재로 채팅 UI·히스토리 본문 불가. 패널은 사이드바 크기에 네트워크 차단 | 제외 |
| `orca-main` 포크 | 모든 내부 데이터 접근과 UI 수정 가능 | 소스가 설치본보다 45패치 뒤짐. Electron 빌드·업스트림 추적 부담이 계속 발생. 로컬 소스에 git 이력 없음 | 제외 |
| 별도 데스크톱 앱 (Orca CLI 엔진) | 4개 화면 전부 가능, UI 자유, Orca 업데이트와 독립 | Orca CLI 호출 비용·폴링 필요, Orca 미실행 시 제어 불가, Pi 세션 포맷 변경 추적 필요 | **선택** |

## 결과 (Consequences)

- 장점: 화면 구성과 데이터 모델을 자유롭게 정할 수 있고, Pi 세션 본문·도구 결과까지 그래프로 만들 수 있다. Orca가 업데이트되어도 앱 UI는 영향받지 않는다.
- 단점: Orca와 별개 프로세스이므로 상태 일관성을 폴링으로 맞춰야 한다. Orca가 실행 중이 아니면 실시간 기능과 제어가 비활성화된다. Pi 세션 포맷이 공개 계약이 아니라 파싱 계층이 깨질 수 있다.
- 되돌리기 비용: 플러그인 경로로 되돌리려면 채팅·히스토리 화면을 포기해야 하고, 포크 경로로 바꾸려면 UI 전체를 Orca 안으로 옮겨야 한다. 어느 쪽이든 상당한 재작성이 필요하다.

## 후속 작업

- 앱 스택, 인덱스 저장 방식, 폴링 세부 주기는 설계 단계에서 정한다.
- `orca agent launch --agent pi` 지원 여부를 실제 실행으로 검증해야 한다(미검증).
- Orca 미실행 시 동작은 [[SPEC-graph-pi-ade]] 에서 히스토리 열람 전용으로 확정했다.
